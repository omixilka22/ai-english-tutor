# Календарний розклад на тиждень

Розклад складається з конкретних занять на понеділок–неділю (Europe/Kyiv).
Створення посеред тижня дозволяє лише майбутні дні й час цього тижня.
У меню можна перейти до наступного тижня та скласти його завчасно.
Збереження одразу публікує заняття для учня, без окремої чернетки.
Нагадування залишаються 12 год / 1 год учню, 1 год / посилання за 15 хв викладачу.
Проведення підтверджує викладач після закінчення заняття; історія зберігається.

Неділя 20:00: фоновий worker раз на хвилину перевіряє потребу в запиті.
«Повторити» копіює звичайні заняття попереднього календарного тижня за їх
фактичними днем і часом (з урахуванням перенесень). Видалені, скасовані та
разові додаткові заняття не копіюються. Копіювання не потребує підтвердження
проведення минулих уроків. Без відповіді нові заняття не створюються.
«Скласти новий» відкриває ручне планування. Уже створені уроки не видаляються.
При ручному додаванні тиждень вважається спланованим; автоматичного запиту
для нього вже не буде. Зміни робляться в картках конкретних занять.

Рішення та ID запиту зберігаються в PostgreSQL. Повторне натискання не
дублює уроки. Якщо бот був вимкнений у неділю, після запуску він надішле
запит для поточного тижня; прострочені години не копіюються. За неоднозначного
часу переведення годинника потрібно вручну вибрати інший час. Тайм-аут Telegram
може спричинити повторне повідомлення (доставку до тайм-ауту неможливо визначити),
але рішення і створення занять залишаються ідемпотентними.

## Перехід зі старої версії

Зупинити бот та окремо запущені старі генератори. Застосувати файли,
виконати `alembic upgrade head`, запустити бот. Нових залежностей немає.
Міграція a9632be54d78 додає week_start і week_renewals.
Вона приховує лише незмінені автоматичні майбутні заняття за межами поточного
тижня без підтвердження проведення, транскрипту або аналізу. Їхні ID збережені
в calendar_week_retired_lessons. Дані не видаляються фізично.
Ручні перенесення, додаткові уроки, скасування та історія зберігаються.
Старий hourly lesson_generator більше не створює занять.

Перевірки: `python -m unittest discover -s tests`.
Перевірка SQL міграції виконана офлайн; застосування до живої БД і реальна
доставка недільного повідомлення потребують запуску в оточенні власника.
