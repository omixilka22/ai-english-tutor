# Recall + Google Meet: тестування на Mac

## Що реалізовано

Викладач відкриває конкретний урок → «Транскрибація» → «Почати транскрибацію».
Помічник приєднується за збереженим посиланням учня. Викладач впускає його у Meet.
Після завершення запису Recall розпізнає текст із автоматичним визначенням мови.
Бот отримує текст через підписані вебхуки, просить визначити викладача серед двох учасників
і запускає Gemini після окремого підтвердження проведення уроку.
Після перевірки аналізу викладачем працює наявне надсилання PDF учню.

Відповідність уроку визначається збереженими session_id, bot_id та recording_id,
а не самим повторно використовуваним посиланням Meet. Автоматичного запуску за розкладом поки немає.
Повторне натискання кнопки не створює другого помічника. Запуск дозволений за 15 хвилин до уроку
та до його запланованого завершення; прострочений запуск після ввімкнення Mac відхиляється.

Запис обмежений часом уроку з запасом 15 хвилин; можна завершити його кнопкою.
Текст із невизначеними ролями можна аналізувати без їх призначення: Gemini не має вгадувати,
кому належать репліки. У цьому MVP підтримано одну сесію запису на урок.

## 1. Застосувати оновлення

Зупиніть бота. Запустіть наданий `apply_recall_integration.py` — він перевірить попередні версії
файлів і збереже резервні копії. Він не змінює `.env` і не виконує міграції самостійно.
Потім у корені Bot_Teacher, з активованим `.venv`:

```sh
alembic upgrade head
```

Міграція додає таблиці `recall_sessions` і `recall_events`. Перед міграцією робочої бази
збережіть її звичну резервну копію. Старі уроки не переписуються.

## 2. Налаштувати локальні секрети

У `.env` залиште вже додані ключ і регіон:

```dotenv
RECALL_API_KEY=ваш_ключ
RECALL_BASE_URL=https://eu-central-1.recall.ai
RECALL_WEBHOOK_SECRET=whsec_ваш_секрет
RECALL_WEBHOOK_READY=false
```

У Recall, у тому самому EU workspace, відкрийте Developers → API Keys & Secrets →
Create Workspace Secret. Збережіть секрет підпису вебхуків у `RECALL_WEBHOOK_SECRET`.
Це окремий секрет, не API key. Ключі не потрібно надсилати в чат або комітити.
Інструкція: https://docs.recall.ai/docs/authenticating-requests-from-recallai

## 3. Приймач вебхуків — термінал 1

У корені проєкту, з активованим `.venv`:

```sh
python -m uvicorn app.recall_gateway:app --host 127.0.0.1 --port 8001
```

Відкрийте `http://127.0.0.1:8001/health`: очікується `{"status":"ok"}`.
Для тунелю використовуйте саме `app.recall_gateway:app`.
Наявний `app.main:app` має інші маршрути й не призначений для публічного доступу.

## 4. Тунель — термінал 2

Встановіть `cloudflared` за офіційною інструкцією:
https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/

Якщо користуєтеся Homebrew, встановлення доступне командою `brew install cloudflared`.
Після встановлення:

```sh
cloudflared tunnel --url http://127.0.0.1:8001
```

Скопіюйте показану HTTPS-адресу виду `https://...trycloudflare.com`.
У Recall → Webhooks додайте адресу:

```text
https://...trycloudflare.com/webhooks/recall
```

Підпишіть endpoint на події:

- `recording.done`, `recording.failed`, `recording.deleted`;
- `transcript.done`, `transcript.failed`;
- `bot.joining_call`, `bot.in_waiting_room`, `bot.in_call_recording`;
- `bot.call_ended`, `bot.done`, `bot.fatal`.

Quick Tunnel не потребує домену чи акаунта Cloudflare, але адреса змінюється при новому запуску.
Після зміни адреси оновіть endpoint у Recall. Не додавайте email-захист тунелю:
вебхуки не проходять інтерактивний вхід; їх перевіряє підпис у нашому приймачі.
Цей спосіб призначений для тестування, без гарантії доступності.
https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

## 5. Увімкнути інтеграцію — термінал 3

Після налаштування endpoint змініть у `.env`:

```dotenv
RECALL_WEBHOOK_READY=true
```

Перезапустіть приймач у терміналі 1. У терміналі 3, у корені проєкту та `.venv`:

```sh
python -m app.check_recall
python -m app.bot.bot
```

Перша команда перевіряє тільки локальну наявність налаштувань, не справжність ключа
і не доступність вебхуків. Worker Recall запускається разом із Telegram-ботом.
Три процеси, база даних і Mac мають залишатися ввімкненими; сон Mac перериває обробку.

## 6. Короткий наскрізний тест

1. Створіть короткий урок на поточний час і перевірте посилання Meet у картці учня.
2. Відкрийте Meet, запросіть другого учасника з окремого пристрою/акаунта.
3. У боті відкрийте урок → «Транскрибація» → «Почати транскрибацію». Впустіть помічника.
   Учасники мають знати, що розмова записується та обробляється.
4. Поговоріть 2–3 хвилини англійською й українською, включно зі зміною мови в одній репліці.
5. Натисніть «Завершити запис», дочекайтеся отримання тексту. Визначте викладача.
6. Після запланованого завершення уроку підтвердьте «Урок проведено».
7. Перевірте аналіз, підтвердьте надсилання і переконайтеся, що учень отримав PDF.
8. Перевірте стан транскрибації: після наступного проходу worker має завершитися видалення.

Цей тест витрачає баланс Recall. Якість змішаного мовлення й правильність поділу учасників
потрібно оцінити на реальній розмові; програмні тести цього не вимірюють.

## Зберігання та збої

- Локальний транскрипт зберігається у PostgreSQL, таблиця `transcripts`; аудіо на Mac не завантажується.
- Після успішної відповіді Telegram про надсилання PDF локальний транскрипт видаляється.
  Worker окремо видаляє транскрипт і запис у Recall; збій цього запиту повторюється пізніше.
  Аналіз і матеріали уроку залишаються.
- Для Recall-тексту встановлено граничний термін 7 діб від запуску, з попередженням за добу.
  Прострочення або скасування уроку запускає очищення навіть без PDF. Локальне очищення
  відбувається лише під час роботи worker. У Recall явно задано 168 годин зберігання запису
  від готовності запису — це незалежна страховка, а не гарантія одночасного видалення.
- Невдале надсилання PDF саме по собі не видаляє текст до закінчення терміну.
- Видалення з робочої БД не очищує її резервні копії. Зберігання даних у Gemini
  регулюється окремими умовами використовуваного API.
- Після неоднозначної мережевої помилки платний POST не повторюється автоматично.
  Перевірте стан бота/транскрипту в Recall та доставку подій; після відновлення endpoint
  повторно надішліть відповідну подію через інструменти Recall, якщо це доступно.
  Не запускайте другого помічника для обходу невизначеного стану.
- Текст довший за 200 000 символів відхиляється явно, не обрізається непомітно.
- Міграція перевірена генерацією PostgreSQL SQL, без застосування до вашої робочої БД.
  Автоматичні тести використовують підроблені API-відповіді. Реальний Recall/Meet тест ще необхідний.
