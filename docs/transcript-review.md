# Транскрипт → Gemini → перевірка → учень

## Налаштування

Додайте у локальний `.env` (не комітьте ключ):

```dotenv
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-3.8-flash
```

Ключ створюється в [Google AI Studio](https://aistudio.google.com/apikey).
Модель можна змінити на доступну вашому API-акаунту модель з підтримкою structured outputs.
Адаптер використовує aiohttp, який вже встановлюється разом з aiogram;
новий Google SDK для цього кроку не потрібен.

Після застосування змін зупиніть старий процес бота, запустіть PostgreSQL,
в активованому venv виконайте `alembic upgrade head`, потім `python -m app.bot.bot`.
Міграція `d6309eb21a45` додає стан черги, версію чернетки та облік доставки.
Без ключа інші функції бота працюють, транскрипт зберігається, а аналіз показує
помилку налаштування. Після додавання ключа перезапустіть бота й натисніть повтор.

## Викладач

«Мої учні» → учень → «Матеріали уроків» → заняття → «Додати транскрипт».
Список містить останні 100 минулих нескасованих занять. Додавання дозволене
після завершення запланованої тривалості уроку та явного підтвердження викладачем «Урок проведено». Є також кнопка матеріалів
у картці конкретного заняття.

Надішліть текст (за потреби кількома повідомленнями) або `.txt` у UTF-8,
до 256 КБ і 60 000 символів сукупно. Файл доповнює вже введений текст.
Натисніть «Завершити», перегляньте початок і кількість символів та підтвердьте.
До цього підтвердження текст існує лише в пам'яті FSM: вихід у меню або
перезапуск бота скасовує незбережене введення. Після підтвердження транскрипт
і завдання аналізу зберігаються однією транзакцією.

Бот надсилає викладачу повідомлення про готовність або помилку аналізу.
Чотири блоки: підсумок, помилки з поясненнями, словник, запропоноване домашнє
завдання. Кожен блок можна редагувати (до 2800 одиниць UTF-16 для безпечного
відображення в Telegram). Перемикайте блоки кнопками; на четвертому є
«Підтвердити й надіслати». Окремий екран підтверджує цю дію.

Учень не бачить чернетку. Після підтвердження матеріали доступні в його меню,
а бот формує та надсилає один PDF з усіма чотирма блоками та кнопкою перегляду в боті.
Редагування підтвердженої версії закрите. Заміна транскрипту та регенерація
готової чернетки в цей крок не входять; невдалий аналіз можна повторити.

## Надійність і межі

- Очередь зберігається в PostgreSQL; worker запускається разом із ботом і
  опитує її кожні 10 секунд. Зупинка процесу не втрачає підтверджений транскрипт.
- Запис заняття блокується на час обробки (Gemini: до 95 с, Telegram: 20–30 с).
  Це запобігає одночасному надсиланню та зміні чернетки. Інші уроки доступні,
  але цей урок/учень можуть чекати завершення запиту. Це проста реалізація MVP.
- Всі дії перевіряють власника. Перед надсиланням перевіряються актуальні ролі,
  зв'язок учня з викладачем, видалення/скасування уроку. Застаріле підтвердження
  після редагування відхиляється за номером версії.
- Для HTTP 500/502/503/504 Gemini викликається до трьох разів загалом, з паузами
  30 і 60 секунд, збереженими в БД. Інші помилки потребують ручного повтору.
  Точний HTTP-код показується викладачу. Повтори можуть витрачати квоту API. Після аварійного переривання
  до commit незавершений AI-запит може виконатися повторно й витратити квоту.
- Доставка учню має до 5 спроб; Forbidden/BadRequest завершуються відразу,
  RetryAfter дотримується затримки, мережеві помилки використовують backoff.
  При помилці доставки матеріали залишаються доступними в меню учня.
- Повторне натискання не дублює підтвердження. Однак аварія після прийняття
  повідомлення Telegram і до commit може спричинити повторну доставку.
  Перед ручним повтором після невизначеної мережевої помилки перевірте чат учня.
- Повідомлення викладачу має до 5 спроб; після відмови Telegram результат
  залишається доступним у меню. Поле review_notified означає завершення цих спроб.
- SQL echo вимкнено, щоб транскрипти й матеріали не друкувалися з параметрами SQL.
  Адаптер не логує ключ, текст транскрипту та тіло помилки провайдера.
- Вхідний транскрипт є даними, а не інструкціями для AI. Відповідь строго
  перевіряється на чотири текстові блоки; обірваний/заблокований результат
  не перетворюється на готовий аналіз. Фактичну точність перевіряє викладач.
- Старі аналізи, створені через попередній API, мають workflow_state=legacy
  і не надсилаються автоматично. Цей Telegram-процес не додає авторизацію
  до старих FastAPI routes; їх не слід виставляти публічно без окремого захисту.
- Автоматичне отримання транскриптів Google Meet ще не підключене.

## Перевірка

```bash
python -m unittest discover -s tests
```

Тести використовують підмінені БД, Gemini та Telegram. Live-запити до Gemini,
міграцію на реальній PostgreSQL і надсилання в Telegram потрібно перевірити
на тестовому завершеному занятті після налаштування ключа.

REST-формат звірено з офіційними джерелами:
[Structured outputs](https://ai.google.dev/gemini-api/docs/generate-content/structured-output?hl=en),
[GenerateContent API](https://ai.google.dev/api/generate-content).


## Явне підтвердження проведення

Міграція `e7410fc32b56` додає `Lesson.conducted_at` і `conducted_by`.
Вона не вважає старі заняття проведеними за датою, статусом або наявністю
транскрипту. Старі матеріали зберігаються, але обробка, надсилання та доступ
учня до них чекають ручного підтвердження викладача.

У списку минулих занять ○ означає «не підтверджено», ✓ — «проведено».
Викладач відкриває урок і вибирає «Урок проведено» або «Урок не відбувся»,
потім підтверджує дію. Другий варіант скасовує минуле заняття й блокує його
непідтверджені матеріали, не змінюючи регулярний розклад. Уже підтверджені
або надіслані матеріали не можна скасувати цим способом.

Тільки дія викладача встановлює факт проведення. Worker більше не записує
PROCESSING/COMPLETED/READY_FOR_REVIEW/APPROVED/SENT у статус заняття:
стан аналізу і доставки зберігається виключно в LessonAnalysis.

## Діагностика Gemini

З папки проєкту з активованим venv:

```bash
python -m app.check_gemini
python -m app.check_gemini --probe
```

Перша команда читає список доступних моделей і перевіряє GEMINI_MODEL.
Друга також перевіряє генерацію на короткому вигаданому діалозі, якщо модель
знайдена (один API-запит, витрачає квоту). Реальні транскрипти не передаються;
ключ, вміст .env і відповіді моделі не друкуються. Значення .env не змінюються.
Це відрізняє проблему доступності моделі/сервісу від обробки конкретного уроку.


## PDF і очищення сповіщень

Перед запуском встановити додаткову залежність у venv:

```bash
python -m pip install -r requirements-pdf.txt
alembic upgrade head
```

Після підтвердження викладачем worker формує PDF із фінального тексту чотирьох
блоків. PDF містить дату/час уроку, імена учня та викладача, виділені заголовки,
лінії, окремі записи словника й номери сторінок. Довгий текст переноситься
на додаткові сторінки без обрізання. Збережені переноси рядків враховуються;
нові запити Gemini також явно вимагають окремі рядки для слів і прикладів.
Текст викладача не передається повторно до AI для оформлення PDF.

ReportLab генерує документ у пам'яті, в окремому потоці, без тимчасових файлів
із даними учня на диску. Шрифти DejaVu з кирилицею і ліцензією входять у проєкт
та вбудовуються в PDF. Деякі декоративні emoji замінюються текстовими позначеннями,
невідомі гліфи відображаються як U+код замість чорних квадратів.

Якщо генерація PDF не вдалася, надсилання не виконується й стан sent не
встановлюється. Бот показує помилку та дозволяє повторити після виправлення.
Уже надіслані раніше TXT-файли автоматично повторно не надсилаються.

Міграція `f8521ad43c67` додає `users.material_notice_id` для одного службового
сповіщення викладачу. Наступний результат/помилка оновлює це сповіщення.
Коли викладач відкриває екран меню, воно видаляється; ID зберігається між
перезапусками. Команди /start та PDF учня не видаляються.

Стара версія не зберігала ID своїх сповіщень, тому автоматично знайти всі старі
повідомлення неможливо. Натискання «Перевірити аналіз» на старому повідомленні
дозволяє прибрати саме його; їх також можна видалити вручну в Telegram.
Обмеження Telegram на видалення старих повідомлень можуть завадити очищенню.

Перевірка самого PDF за наявності тестової залежності pypdf:

```bash
python -m pip install pypdf
python -m unittest discover -s tests -p test_lesson_pdf.py
```
